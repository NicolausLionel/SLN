## Workflow

1. Confirm the module, learner profile, roles and deliverables.
2. Research reliable sources and record references as you go.
3. Draft the outline and shared Markdown.
4. A teammate reviews for accuracy, clarity and beginner-friendliness.
5. Build the Study Guide, Test Bank, PPT and videos from the reviewed source.
6. Run peer review and test the questions and examples. Record issues and assign corrections.
7. Propagate approved corrections to every affected resource.
8. Rehearse the mini lecture, collect feedback, revise.
9. Check files, links, permissions, filenames, logs and evidence before submitting.

**Communication.** WeChat and WhatsApp for quick questions. GitHub Issues, commits and pull requests for tasks, changes and reviews. Regular progress checks record decisions, blockers and owners. Each member keeps a personal log of work and significant AI assistance.

## Risks and mitigation

| Risk | Mitigation |
|---|---|
| Module or topic not decided | Discuss with the team or teacher and confirm first |
| Uneven workload or missed deadlines | Give each member a clear task and check progress regularly |
| Explanations wrong or too difficult | Use reliable sources and have teammates check |
| Changes not carried into all materials | Treat the latest Markdown as the source and update the rest |
| GitHub or file access problems | Check access early and keep local backups |
| Video or presentation delayed | Write scripts early and leave time to practise and test equipment |
